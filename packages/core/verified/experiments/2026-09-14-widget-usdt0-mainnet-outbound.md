## What this proves, and what it does not

Proves: `Usdt0LayerZeroAdapter`'s outbound `send()` path (quote -> build -> real wallet signature ->
submit -> track) works correctly end to end on real mainnet, for a real Stellar -> Arbitrum USDT0
transfer, with the amount and recipient landing exactly as requested — independently verified on
both chains, not solely from any single service's own report.

Does NOT prove: behavior on any destination chain other than Arbitrum (13 chains are configured in
`USDT0_EVM_CHAINS`; only this one has now been proven for real); behavior under
load/concurrency/retry scenarios; inbound (EVM -> Stellar) USDT0, which remains **BLOCKED** per
`2026-09-11-inbound-usdt0-c-address.md` and `2026-09-11-inbound-usdt0-no-trustline.md` (both still
need a real mainnet operator to resolve their own open questions); any security review of this code
path (none has been done — see `packages/relayer/OUTBOUND_THREAT_MODEL.md`'s equivalent framing for
the CCTP outbound direction, which this rail has no equivalent document for yet).
